# xsoc 1.0.5

## 本次变更

- Windows MSI 的服务和状态登记组件使用 XSOC 独立、固定的组件 GUID，避免与不同资源路径的其他产品共享组件引用。升级仍在安装新组件前于同一事务中移除旧产品，维修与失败回滚保留现有事务规则。
- Windows 维护程序对明确命名的日志 writer/read 锁文件校验已打开的安全对象及零长度，不再读取可能被独占锁定的字节。普通日志仍执行原有有界读取，文件类型、重解析点、多硬链接、所有者和 ACL 校验继续生效。
- 安装、维修及回滚需要主动停止服务时，保留原服务进程句柄，并在服务状态变为 Stopped 后有界等待该进程退出。普通 MSI 卸载继续使用 `StopServices`；服务在销毁 Tokio runtime 后才报告 Stopped，残余进程或外部日志查看器的锁文件通过对象校验处理。
- 状态及事务目录查询只将 `NotFound` 视为缺失，其他元数据错误会返回失败，避免保留、清理或提交步骤误报成功。
- 软件版本和各平台安装包版本统一为 1.0.5，安装示例同步更新。

## 验证与范围

Windows CI 覆盖真实 MSI 安装、维修、卸载、状态保留和失败回滚，并增加持锁卸载及具有旧冲突 GUID 的隔离外部产品 MSI 共存场景。外部产品为测试夹具，不代表对用户本机 UnionC 安装包的实测。

不增加旧 HostMonitor 的迁移兼容层，也不清理用户机器上已有的孤立服务。本地 Linux 检查不能替代 Windows 原生生命周期验证；正式资产以此标签对应完整 CI 和发行工作流的成功结果为准。

继续固定官方 `xcsc 1.0.4`（`9cff5bc1425072533fcb8984ee4820b1f6ab6a5c`），复用现有安全文件句柄 API。遥测、配对和持久状态合同保持现有格式。

组件规则依据：[Microsoft Windows Installer 组件标识规则](https://learn.microsoft.com/en-us/windows/win32/msi/changing-the-component-code)。锁文件行为依据：[Microsoft LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex)。
